# Trials install exact Spliced states, never re-resolved

Every Trial installs a Spliced state with `npm ci`. That state is the Good state's lockfile with whole Change groups copied in from the Bad state's lockfile, so every installed version comes from one of the two real lockfiles and the Culprit we report is a version the user actually had. The rejected alternative is **re-resolving**, which is what depbisect and lockbisect do: revert specs in `package.json` (or force versions through `overrides`) and let `npm install` resolve a new tree. That makes any subset installable, but a Trial can then install versions that exist in neither lockfile, and the same Trial can resolve differently from one day to the next. We accept the costs in exchange for reproducible, honest Trials. Change groups must be computed as coupling closures and can be large, and bisecting inside a group is rarely possible. [The splice spike](../spikes/splice-lockfile.md) showed that `npm ci` installs a consistent Spliced state exactly, leaves its lockfile byte-for-byte unchanged, and refuses an inconsistent one instead of re-resolving it.
